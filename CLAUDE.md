# Instructions for further work

Read `README.md`, `docs/ART_PIPELINE.md`, and the [open issues](../../issues)
before making changes. Start with the highest-priority open issue unless the
user asks for something else.

## Important rules

1. Do not hand-edit `tamagotchi_arcade/cat_sprites.h` or
   `tamagotchi_arcade/premium_assets.h`. They are generated by the tools in
   `tools/`.
2. Do not solve depth problems by picking arbitrary horizontal rows from a
   flat sprite sheet. The goal is explicit back and front layers.
3. The cat in `cat_sprites.h` is the reference for fit. All cosmetic sprites
   should be previewed on the actual compiled cat.
4. Keep the generator, simulator, and firmware in agreement. A changed
   anchor, mask, or layer rule isn't done until it's visible in the
   simulator.
5. Run both simulators and compile the firmware before delivering.
6. Only flash a physical ESP32 when the user explicitly asks. Find the port
   with `arduino-cli board list`; use 115200 baud on this device.
7. Preserve the user's other changes. Don't delete style sheets or old
   simulator images before a replacement is approved.

## Definition of done for graphics

A cosmetic change is done when:

- it has clean transparency with no green fringe or foreign image
  fragments;
- it sits naturally on the neutral, happy, blinking, excited, and sad cat;
- it's checked with and without relevant ear/hat occlusion;
- the back part never paints over the face, chest, or paws;
- the front part only covers anatomically correct attachment points;
- the shop preview is still legible;
- the simulator shows exactly the same RGB565 data and layers as the
  firmware;
- `arduino-cli compile --fqbn esp32:esp32:esp32 tamagotchi_arcade` succeeds
  (see `README.md` for the full command with build properties).

## Current technical debt

Accessories come from fixed crops of `cosmetics_style_guide.png`. They're
scaled, chroma-keyed, and placed into one flat 28×26 sprite per item.
`art.cpp` then tries to create depth with item-specific row selections. This
is why scarves and capes can look clipped or unnatural. Don't spend more time
fine-tuning row numbers; carry out the explicit-layers and redraw work
tracked in the open issues instead.
